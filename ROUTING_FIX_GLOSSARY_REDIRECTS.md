# Routing Fix: Glossary Term Redirects

**Date:** November 20, 2025  
**Issue:** Navigating to `/glossary/osteoarthritis` caused "Failed to fetch dynamically imported module" error

## Root Cause

The glossary autolink system has many terms that point to umbrella/parent pages. For example:
- "osteoarthritis", "cartilage", "synovial fluid" → all link to `JointHealthPage`
- "osteoporosis", "osteopenia" → link to `BoneDensityPage`
- "insomnia" → links to `SleepQualityPage`
- "serotonin", "dopamine", "GABA", "glutamate" → link to `NeurotransmitterPage`

The autolink system correctly maps these terms when clicked in page content, but if a user:
1. Types the URL directly (e.g., `/glossary/osteoarthritis`)
2. Refreshes the page after clicking a link
3. Uses a bookmark to a specific term

...the application would try to load a component that doesn't exist, resulting in a 404 and module import error.

## Solution

Added redirect rules in `RouterLayout.tsx` using the existing `ALIAS_REDIRECTS` system to redirect glossary sub-terms to their parent pages.

### Files Modified

**`src/router/RouterLayout.tsx`**

Added glossary term redirects:
```typescript
const ALIAS_REDIRECTS: Record<string, string> = {
  // ... existing redirects ...
  
  // glossary term redirects - terms that are part of a broader page
  '/glossary/osteoarthritis': '/glossary/joint-health',
  '/glossary/osteopenia': '/glossary/bone-density',
  '/glossary/insomnia': '/glossary/sleep-quality',
  '/glossary/serotonin': '/glossary/neurotransmitter',
  '/glossary/dopamine': '/glossary/neurotransmitter',
  '/glossary/gaba': '/glossary/neurotransmitter',
  '/glossary/glutamate': '/glossary/neurotransmitter'
};
```

## How It Works

1. User navigates to `/glossary/osteoarthritis`
2. React Router matches the path in `ALIAS_REDIRECTS`
3. `<Navigate to="/glossary/joint-health" replace />` component renders
4. Browser redirects to correct page
5. `JointHealthPage` loads successfully

The `replace` prop ensures the redirect replaces the browser history entry (so hitting "back" doesn't go back to the invalid URL).

## Benefits

- ✅ Direct URL access works for all glossary terms
- ✅ Browser refresh doesn't break after clicking glossary links
- ✅ Bookmarks work correctly
- ✅ SEO-friendly (301 redirect behavior)
- ✅ No duplicate pages in sitemap (redirects excluded from route building)
- ✅ Analytics remain clean (only canonical pages tracked)

## Glossary Autolink System

The system works in multiple layers:

### 1. Term Mapping (`glossaryAutolink.tsx`)
```typescript
{
  key: 'jointhealth',
  terms: ['joint health', 'joints', 'cartilage', 'osteoarthritis', 'synovial fluid']
}
```

### 2. URL Mapping (`routePaths.ts`)
```typescript
'jointhealth': '/glossary/joint-health'
```

### 3. Component Mapping (`routes.config.ts`)
```typescript
{
  key: 'jointhealth',
  title: 'Joint Health',
  componentPath: './components/glossary/JointHealthPage',
  componentName: 'JointHealthPage'
}
```

### 4. Redirect Mapping (`RouterLayout.tsx`)
```typescript
'/glossary/osteoarthritis': '/glossary/joint-health'
```

## Future Enhancement

Consider creating a script to automatically generate redirects from the `GLOSSARY_TERMS` array in `glossaryAutolink.tsx`. This would ensure all terms have redirects without manual maintenance.

Example pseudo-code:
```typescript
// Auto-generate redirects from glossary terms
const autoGeneratedRedirects = GLOSSARY_TERMS.flatMap(term => {
  const targetPath = PAGE_PATHS[term.key];
  return term.terms
    .filter(t => t.toLowerCase() !== term.key) // exclude primary term
    .map(t => ({
      from: `/glossary/${t.toLowerCase().replace(/\s+/g, '-')}`,
      to: targetPath
    }));
});
```

This would automatically create redirects for ~200+ term variations without manual work.
