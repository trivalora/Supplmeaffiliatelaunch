# v0.7.0 Knowledgebase Content Migration Plan

**Target Version**: v0.7.0  
**Date Created**: December 5, 2025  
**Status**: Planning Phase  
**Owner**: Database Migration Team  
**Estimated Duration**: 2-3 weeks

---

## Executive Summary

Migrate all knowledgebase content from hardcoded TSX files to database-driven plain text storage. This enables:

- ✅ **Automatic glossary term linking** (31 orphaned terms will auto-link)
- ✅ **Content updates without code deploys** (CMS-like editing)
- ✅ **Consistent content management** (single source of truth)
- ✅ **CSS-based styling** (separation of content and presentation)
- ✅ **Scalability** (easier to add new supplements)

---

## Current State (v0.6.15)

### Content Storage

All knowledgebase content is hardcoded in TSX component files:

```
src/components/pages/supplements/
├── AshwagandhaKnowledgebasePage.tsx
├── CalciumKnowledgebasePage.tsx
├── CollagenKnowledgebasePage.tsx
├── ... (17 total files)
```

### Content Types

Each supplement has:

1. **Hero Description** - ✅ Plain text (already autolinkable)
2. **Overview Content** - ❌ JSX (cannot autolink)
3. **Additional Overview** - ❌ JSX (cannot autolink)
4. **Benefits** - ✅ Plain text array (already autolinkable)
5. **Drawbacks** - ✅ Plain text array (already autolinkable)
6. **Buying Guide** - ⚠️ Mixed (plain text + some JSX)
7. **Research Grades** - ✅ Plain text (already autolinkable)
8. **References** - ✅ Plain text array (already autolinkable)

### Problem

**JSX content bypasses autolinking**:

```tsx
// ❌ Current (no autolinking)
overviewContent: (
  <p>
    Ashwagandha is an <span className="font-medium">adaptogen</span>...
  </p>
)
```

**Result**: 31 glossary terms have no incoming links despite appearing in content.

### Phase 2: Content Extraction (Week 1-2)

**Tasks**:

1. ⏳ Create extraction script `scripts/extract-knowledgebase-content.mjs`
2. ⏳ Parse all 17 TSX files
3. ⏳ Extract text from JSX nodes
4. ⏳ Generate SQL INSERT statements
5. ⏳ Validate extracted content

**Extraction Script**:

```javascript
// scripts/extract-knowledgebase-content.mjs
import { readFileSync, writeFileSync } from 'fs';
import { parse } from '@babel/parser';
import traverse from '@babel/traverse';

const SUPPLEMENTS = [
  'Ashwagandha', 'BCAA', 'Calcium', 'Casein', 'Collagen',
  'Creatine', 'Curcumin', 'Iron', 'Magnesium', 'Multivitamin',
  'Omega3', 'Prebiotics', 'Probiotics', 'Sulforaphane',
  'VitaminC', 'VitaminD', 'WheyProtein'
];

function extractTextFromJSX(node) {
  // Recursively extract text from JSX, ignoring <span> wrappers
  if (node.type === 'JSXText') return node.value;
  if (node.type === 'JSXElement') {
    return node.children.map(extractTextFromJSX).join('');
  }
  return '';
}

function extractContent(filePath) {
  const code = readFileSync(filePath, 'utf-8');
  const ast = parse(code, { sourceType: 'module', plugins: ['jsx', 'typescript'] });
  
  const content = {
    overviewContent: null,
    additionalOverviewContent: null,
  };
  
  traverse(ast, {
    ObjectProperty(path) {
      if (path.node.key.name === 'overviewContent') {
        content.overviewContent = extractTextFromJSX(path.node.value);
      }
      if (path.node.key.name === 'additionalOverviewContent') {
        content.additionalOverviewContent = extractTextFromJSX(path.node.value);
      }
    }
  });
  
  return content;
}

// Process all supplements
const sqlStatements = [];
SUPPLEMENTS.forEach(supplement => {
  const slug = supplement.toLowerCase().replace(/\s+/g, '-');
  const filePath = `src/components/pages/supplements/${supplement}KnowledgebasePage.tsx`;
  const content = extractContent(filePath);
  
  sqlStatements.push(`
UPDATE api.supplements SET
  overview_content = '${content.overviewContent.replace(/'/g, "''")}',
  additional_overview_content = '${content.additionalOverviewContent.replace(/'/g, "''")}'
WHERE slug = '${slug}';
  `);
});

writeFileSync('scripts/generated-content-migration.sql', sqlStatements.join('\n'));
console.log('✅ Content extraction complete!');
```

**Deliverables**:
- Extraction script
- Generated SQL with all content
- Validation report (missing/malformed content)

// src/components/sections/knowledgebase/OverviewSection.tsx

import { autolinkGlossaryTerms } from '@/lib/glossaryAutolink';

interface OverviewSectionProps {
  overviewTitle?: string;
  overviewContent: string | React.ReactNode; // Support both during migration
  dietarySources?: DietarySource[];
  additionalOverviewContent?: string | React.ReactNode;
  currentPage?: string; // For self-link prevention

export function OverviewSection({
  overviewTitle = "What is this supplement?",
  overviewContent,
  dietarySources,
  additionalOverviewContent,
  currentPage

  // Process autolinking if plain text
  const linkedOverview = typeof overviewContent === 'string'
    ? autolinkGlossaryTerms(overviewContent, currentPage)
    : overviewContent;
    
  const linkedAdditional = typeof additionalOverviewContent === 'string'
    ? autolinkGlossaryTerms(additionalOverviewContent, currentPage)
    : additionalOverviewContent;

  return (
    <div data-knowledgebase-card-info className="bg-card rounded-[14px] border border-border p-8">
      <h2 className="text-primary mb-6">{overviewTitle}</h2>

      <div data-knowledgebase-content-text className="space-y-4">
        <div className="text-foreground leading-7 overview-text">
          {linkedOverview}
        </div>

        {dietarySources && /* ... */}

        {additionalOverviewContent && (
          <div className="text-foreground leading-7 overview-text">
            {linkedAdditional}
          </div>
        )}
      </div>
    </div>
  );
}

## Risks & Mitigation

### Risk 1: Data Loss During Migration

**Mitigation**:
- Full database backup before migration
- Test extraction script thoroughly
- Manual review of generated SQL
- Keep TSX files as backup until v0.8.0

### Risk 2: Autolinking Breaks Existing Links

**Mitigation**:
- Autolinking skips current page (self-link prevention)
- Test on staging first
- Monitor 404s post-deployment

### Risk 3: Styling Changes

**Mitigation**:
- CSS maintains existing visual design
- Side-by-side comparison screenshots
- User testing before production

### Risk 4: Performance Regression

**Mitigation**:
- Benchmark current performance
- Test database query performance
- Cache rendered content (ISR)
- Monitor Vercel metrics

### Risk 5: Build Time Increase

**Mitigation**:
- Server Components reduce bundle size
- Database queries cached
- Parallel page generation

## Appendix A: Database Schema Changes

```sql
-- Complete schema for v0.7.0
CREATE TABLE IF NOT EXISTS api.supplements (
  -- Existing columns (v0.6.x)
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  slug TEXT UNIQUE NOT NULL,
  name TEXT NOT NULL,
  short_name TEXT,
  category TEXT,
  subcategory TEXT,
  hero_description TEXT,
  quick_overview TEXT,
  extended_overview TEXT,
  science_snapshot TEXT,
  key_benefits TEXT[],
  ideal_for TEXT[],
  timing_tips TEXT[],
  quality_markers TEXT[],
  safety_considerations TEXT[],
  what_to_expect_summary TEXT[],
  typical_dosage_min NUMERIC,
  typical_dosage_max NUMERIC,
  typical_dosage_unit TEXT,
  form_notes JSONB,
  what_to_expect JSONB,
  synergy_notes TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),

  -- NEW columns for v0.7.0
  overview_content TEXT,
  additional_overview_content TEXT,
  buying_guide_intro TEXT,
  buying_guide_items JSONB DEFAULT '[]'::jsonb
);

-- Indexes
CREATE INDEX IF NOT EXISTS idx_supplements_slug ON api.supplements(slug);
CREATE INDEX IF NOT EXISTS idx_supplements_category ON api.supplements(category);

-- Full-text search (future enhancement)
CREATE INDEX IF NOT EXISTS idx_supplements_overview_content_trgm 
  ON api.supplements USING gin (overview_content gin_trgm_ops);

-- Row-level security (existing)
ALTER TABLE api.supplements ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Allow public read access" ON api.supplements
  FOR SELECT TO anon, authenticated USING (true);
```
