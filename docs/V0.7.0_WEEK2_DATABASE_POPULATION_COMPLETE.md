## 🔧 Technical Challenges & Solutions

### Challenge 1: pg_trgm Extension Not Enabled
**Error**: `ERROR: operator class "gin_trgm_ops" does not exist`

**Solution**: Added `CREATE EXTENSION IF NOT EXISTS pg_trgm;` to migration SQL

### Challenge 2: Slug Format Mismatch
**Error**: UPDATE statements returned "No rows returned"

**Root Cause**: 
- Extraction script used hyphenated slugs (`casein-protein`, `whey-protein`)
- Database used shortened slugs (`casein`, `whey`)
- Sulforaphane missing from database entirely

**Solution**:
1. Queried database: `SELECT slug FROM api.supplements ORDER BY slug;`
2. Updated migration SQL to match database slugs
3. Added sulforaphane to database before re-running migration

### Challenge 3: psql Connection Failures
**Error**: `FATAL: Tenant or user not found`

**Root Cause**: Supabase pooler requires specific authentication that wasn't in DATABASE_URL

**Solution**: Used Supabase SQL Editor for all manual queries instead of CLI psql

## 🏆 Key Learnings

1. **Slug Consistency**: Always verify database slug format before generating bulk UPDATE statements
2. **Supabase Pooler**: Direct psql connection has authentication limitations - use SQL Editor for manual queries
3. **Extension Dependencies**: pg_trgm must be explicitly enabled before creating GIN indexes with gin_trgm_ops
4. **Content Extraction**: Plain text extraction from JSX requires careful handling of React fragments, props, and event handlers
5. **Type Flexibility**: Template components benefit from accepting both `string | React.ReactNode` for gradual migration
